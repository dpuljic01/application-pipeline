# Application Pipeline - v1 Specification

## Description
A lightweight CRM-style job search pipeline
CRM = Customer Relationship Management

## Goals
- Track job applications through a defined pipeline
- Log outreach/activity per application
- Automate follow-up reminders
- Keep documents tied to applications
- Provide basic “honesty” metrics - last 7 days (default), optionally 30
    - Applications sent (count)
    - Outreach messages/calls (count)
    - Interviews scheduled (count)
    - Stale applications (no activity for how many days)

## Pipeline Stages
SAVED → APPLIED → SCREEN → TECH → ONSITE → OFFER
             ↘
            REJECTED (terminal)

## Core Entities
- User
- Application
- Activity
- FollowUpRule
- FollowUpReminder (derived/scheduled instance)
- Document

## Core Flows
1) Add application
2) Move stage
3) Log outreach activity
4) Compute next follow-up
5) Send reminder email
6) View application pipeline + stale list + basic weekly stats

## Decisions

### Stage model
- Application.stage is an ENUM (SAVED, APPLIED, SCREEN, TECH, ONSITE, OFFER, REJECTED)
- No Stage table in v1 (stages are fixed)

### Allowed transitions
Forward only:
- SAVED → APPLIED → SCREEN → TECH → ONSITE → OFFER

Terminal:
- ANY → REJECTED

Backwards:
- Not allowed in v1

### Stage change side effects
On any stage change:
- Create Activity(type=STAGE_CHANGE, from_stage, to_stage)
- Set Application.last_activity_at = now
- Set Application.stage_updated_at = now

### When to update last_activity_at
- when any meaningful activity occurs, including:
- stage change
- sending a message (LinkedIn, email, call)
- interview scheduled
- possibly uploading a document (CV, Cover Letter etc..)
